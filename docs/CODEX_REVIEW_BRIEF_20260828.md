### 1d. TEXT_ENCODER changed, EDGE_DIM 512 to 1280

Was laion/CLIP-ViT-B-32-laion2B-s34B-b79K at 512 dims via the transformers class
CLIPTextModelWithProjection. Now uses the project's own ULIPBackbone text tower,
which is open_clip ViT-bigG-14 at 1280 dims. This implements decision U-20,

Rationale to check: the local HuggingFace cache holds only open_clip_model.safetensors
for bigG, with no config.json and no HF-format weights, so from_pretrained would

understandings.

### 4 and 5. New read-only analysis tools

tools/label_duel.py is load-bearing. It produced the evidence used to exclude 21
assets from the corpus, so its correctness is a research concern, not a tooling one.

It runs a two-way forced choice: for each asset it passes four texts in one call to
describe_rank.score_candidates, namely a photo of a LVIS-LABEL, a photo of a
MODEL-LABEL, then the two bare labels. LVIS parenthetical disambiguators are
stripped. A control arm duels a true label against a randomly drawn decoy on rows
where the model agreed with the catalogue.

CHECK for anything that could bias the comparison: candidate ordering, tie handling,
sampling with or without replacement, reuse of the RNG across the control and test
arms, off-by-one in the score bands or quantiles, and whether the reported win rates
could be inflated by how the candidates are constructed.

tools/build_lowclip_sheets.py renders contact sheets. Lower stakes, but it has a
uids-file mode and a relation mode that share BANDS and CHUNKS state; check they
cannot interfere.

## 4. tools/label_duel.py -- provenance and three recorded limits

No behavioural change to the duel itself. Added:
- A provenance block in the output JSON: timestamp, git commit, ranker model and
  version, prompt template, seed, control size, limit, relation, confirmed
  filter, index path and row count, vocab size, tie direction, decoy policy,
  control population. It previously carried only the two result lists, and --out
  defaults to one path, so a differently configured run silently replaced the
  previous file with one of identical shape.
- Three limits written into the module docstring, because they bound the CLAIM
  rather than the code: (1) the win rate is not a catalogue-error rate, since
  divergent mixes real mislabels with legitimate refinements that the annotation
  prompt explicitly asks for, and CLIP prefers the more specific true phrase --
  measured, 947 of 8313 divergent rows have one label a substring of the other;
  (2) the control is easier than the test in two independent ways -- a uniformly
  random decoy, and control rows drawn from category_relation == exact, which is
  by definition the unambiguous subgroup, and which does not imply
  identity_confirmed; (3) ties go to LVIS, and because the action taken on this
  output is exclusion, a tie counts toward deleting.

CHECK: is the provenance block sufficient to reproduce a run. Is any recorded
limit overstated or understated. Do the two reviewers' round-1 findings now have
a home in the artifact rather than only in a message.
