## A. 公式（逐字）與程式對應

**Eq. 6（§2.6）**
```
e_query = Fusion(e_text, e_img, e_pc) + λ · e_layout
```
"where λ is a learnable scalar controlling the contribution of layout information. This residual design allows layout reasoning to enhance retrieval without disrupting the original embedding space."
- 程式 `dual_tower.py QueryTower.forward`：`fused = self.fusion(embeds, present)`；`layout is None → return fused`；否則 `fused + self.lam * layout`，`lam = nn.Parameter(init_lambda)`。✅ 逐項一致。
- `layout=None` 分支就是 Table 1 的 layout-free 評估（§3.2 "evaluating on Objaverse-LVIS (which lacks layout and disables ESSGNN)"）。✅

**Eq. 7 / 8（§2.6）**
```
L_q2g = −log exp(sim(e_q, e_g)/τ) / Σ_{e'_g∈B} exp(sim(e_q, e'_g)/τ)
L_g2q = −log exp(sim(e_g, e_q)/τ) / Σ_{e'_q∈B} exp(sim(e_g, e'_q)/τ)
L_layout = ½(L_q2g + L_g2q)
```
- 程式 `losses.py`：`bidirectional=True` → `½(CE(logits) + CE(logitsᵀ))`；`stage2.py` 建 loss 時 `bidirectional=True`（行 998）。✅
- τ：smoke 記錄 `tau 0.5`（§3.1 "0.5 for all experiments"）。✅
- B = 同批；`unique_positive_batches` 保證一批內 asset_id 不重複（否則 arange(B) 標籤會把真正例算成負例）。✅ 論文沒講，但這是 Eq. 7/8 成立的必要條件。

**Eq. 2（§2.5，特徵更新）**
```
h_i^{l+1} = h_i^l + Σ_{j∈N(i)} f_h(d_ij^l, h_i^l, h_j^l, e_ij; θ_h)
```
- 程式 `essgnn.py ESSGCL.forward`：`m_h = f_h(cat[h_row, h_col, radial, edge_attr])`，`h_next = h + segment_sum(m_h, row)`。✅ 形式一致；f_h 是 MLP（論文 "approximate using multilayer perceptrons"）。
- **d_ij**：正文 Eq. 2 下面寫 `d_ij = ‖x_i − x_j‖_2`（歐氏距離）；**Appendix C Eq. 10–12 用 `‖x_i − x_j‖²`（平方）**。程式 `distance: "squared"`（`essgnn_arch_protocol.json`）→ 採附錄。🟠 **PAPER-INTERNAL CONTRADICTION**（正文 vs 附錄），已知（D0-009）。

**Eq. 3（§2.5，座標更新）**
```
x_i^{l+1} = x_i^l + Σ_{j∈N(i)} (x_i^l − x_j^l) · f_x(d_ij^l, h_i^{l+1}, h_j^{l+1}, e_ij; θ_x)
```
"f_x : R^(2d+1+e) → R^3"
- 程式：`w = f_x(cat[h_for_x_row, h_for_x_col, radial, edge_attr])`，`trans = coord_diff * w`（w 是**標量**），`x + segment_sum(trans)`。
- 兩個不一致：
  1. **f_x 的輸入 h 是第 l 層還是 l+1 層**：正文寫 `h^{l+1}`；附錄 Eq. 13 寫 `φ_x(m_ij)`，而 m_ij 由 `h^l` 算（Eq. 10）。程式 `coord_feat: "current"`（= h^l，附錄讀法）；`"updated"` 選項存在（正文讀法）。🟠 PAPER-INTERNAL CONTRADICTION。
  2. **f_x 的輸出維度**：正文寫 `→ R^3`；附錄 Eq. 13 是標量 `φ_x(m_ij)` 乘向量差。若 f_x 真輸出 R^3 並逐元素乘，**旋轉等變性會壞**（Appendix C 的證明只對標量成立）。程式用標量（附錄）。🟠 PAPER-INTERNAL CONTRADICTION；程式選了讓 Eq. 4 成立的那個。

**h^(0)（§2.5）**
```
h_i^(0) = Concat(x_i, t_i)
```
- **Appendix C 開頭**："We begin by assuming that h^0 is invariant to SE(3) transformations on x" —— 把 x_i 串進 h^(0) 就**不**再對 x 不變，附錄的前提與正文的定義互斥。
- 程式 `h0_mode`：預設 `"semantic"`（h^(0) = t_i，附錄前提）；`"concat_xt"` 選項存在（正文）。`essgnn_arch_protocol.json` **沒有記錄 h0_mode**，走的是程式預設。🔴 **協定漏記**：跑哪一個沒被鎖進 artifact，必須補上。🟠 正文 vs 附錄矛盾本身已記為 D0-009 / RA-1。

**Eq. 4（§2.5，等變性）**
```
(R x^{l+1} + T, h^{l+1}) = ESSGNN(R x^l + T, h^l, E)
```
- 只有「標量 f_x + h^(0) 不含 x + d_ij 只依賴距離」三件同時成立才成立。程式的預設三件都成立；`tests/test_essgnn*.py` 有等變性測試（待確認名稱）。✅ 對附錄版本。

**Pooling（§2.5）**
```
e_layout = Pooling({h_i^(L)})
```
- 論文沒有命名。程式 `pooling: "normalised_sum"`（Kyzen 裁定 DL-077 第 8 項）；另有 mean / sum / max。⚪ IMPLEMENTATION CHOICE（Kyzen 核可）。

## C. Table 1「w/ ESSGNN」怎麼評（PAPER FACT，§3.2 逐字）

> "the fusion layer becomes partially adapted to layout-conditioned features, creating a feature-attribution mismatch when evaluating on Objaverse-LVIS (which lacks layout and disables ESSGNN). A practical mitigation is to maintain two fusion heads: a layout-free head (Stage-1) and a scene-aware head (Stage-2), selected at inference by context availability. Using the Stage-1 head reproduces the 'w/o ESSGNN'…"

設計：
```
w/o ESSGNN 列 = Stage 1 checkpoint；query fusion = Stage 1 的
w/  ESSGNN 列 = Stage 2 checkpoint；query fusion = Stage 2 改過的；layout = None；ESSGNN 不跑；
                gallery 兩列相同（Stage 2 凍 gallery）→ 兩列的差就是 query fusion 被 layout 訓練拉走的量
```
程式現況：**`run_retrieval.py` 沒有 Stage 2 路徑**（grep `stage2|use_layout|layout` 空）。🔴 **缺件**，必須補：載 Stage 2 checkpoint 進 `use_layout=True` 的塔、`layout=None`、gallery 沿用 Stage 1 索引。
